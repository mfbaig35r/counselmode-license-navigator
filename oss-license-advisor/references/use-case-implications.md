# Implications by scenario (editorial view)

| Scenario | Public domain / Permissive | Weak copyleft (LGPL, MPL, EPL) | Strong copyleft (GPL) | Network copyleft (AGPL) | Source-available (SSPL, BUSL, ELv2) | AI model licenses (Llama, Gemma, RAIL) | Practical guidance |
|---|---|---|---|---|---|---|---|
| Internal use only (no distribution, no external users) | No obligations | No obligations | No obligations (GPL FAQ: private modification OK) | No obligations if not exposed to external users; modifications used by external network users trigger §13 | Generally allowed (check non-production limits in BUSL) | Allowed subject to AUP | Internal use is the safest pattern; document it to defend later. |
| Running as backend of your SaaS (users never receive copies) | No obligations | No obligations | No obligations - "SaaS loophole" | If modified and users interact with it remotely: must offer Corresponding Source of modified version | Allowed unless you are offering the software itself / a competing service | Allowed subject to AUP, MAU/revenue thresholds | Map which components users interact with directly. |
| Distributing binaries (desktop app, on-prem, mobile app, SDK) | Include notices/license texts; Apache: NOTICE + state changes | Provide source of the covered library/files; LGPL: allow relinking; no reverse-engineering ban for LGPL part | Combined/derived work must be GPL with full source - incompatible with closed-source distribution | Same as GPL | Check redistribution and sublicensing limits | Include license copy, "Built with Llama" etc.; flow down AUP | Produce an SBOM and attribution file with each release. |
| Embedded / consumer devices (IoT, routers, cars, TVs) | Notices in docs or UI | LGPLv3: Installation Information; relinking | GPLv2: complete corresponding source incl. "scripts used to control compilation and installation," with a written offer (3 years). A Dec. 23, 2025 pretrial order in SFC v. Vizio (Cal. Super. Ct.) read GPLv2/LGPLv2.1 not to require enabling reinstallation such that the device continues to function properly; SFC says it never argued otherwise and calls the ruling irrelevant to its claims (trial-court order, not precedential). GPLv3: Installation Information for User Products (anti-tivoization) is an express, separate duty. | Same plus network | Check | Check | GPLv3 §6 Installation Information remains the express anti-tivoization duty; the Vizio order addressed a point SFC did not contest. Vizio trial reportedly began Aug. 2026; no judgment found as of Nov. 18, 2026. |
| Modifying the open source code | Free; keep notices; Apache: mark changes | Modified files/library must be released under same license on distribution | Modifications are GPL when distributed | Modifications must be offered to network users | Per license; often prohibited to remove license-key checks | Fine-tunes are "derivatives": flow-down applies | Upstream your changes to reduce maintenance and compliance burden. |
| Static linking | Fine | LGPL: must provide object files to allow relinking; MPL: fine (file-level) | Creates a combined work - GPL applies to whole | Same | Per license | N/A | Prefer dynamic linking for LGPL components. |
| Dynamic linking / plugins / IPC | Fine | Fine (LGPL designed for this) | FSF view: dynamic linking usually creates a combined work; separate processes communicating at arm's length (pipes, sockets, CLI) usually do not | Same as GPL | Per license | N/A | Contested legal area - keep GPL components at arm's length (separate process, APIs). |
| Containers / Docker images | Ship notices for all included packages | Provide source for covered components in the image | Distributing an image = distributing GPL components (provide source/offer) | Same | Per license | Same as distribution if weights included | Container images are distributions - scan base images. |
| Licensing YOUR project (choosing an outbound license) | MIT/Apache-2.0 maximize adoption; Apache adds patent protection | MPL-2.0 keeps your files open while allowing commercial embedding | GPL deters proprietary forks; enables dual licensing | AGPL protects against cloud free-riding; reduces corporate adoption | Not open source; reputational and community risk (forks: OpenSearch, OpenTofu, Valkey) | Custom model licenses reduce adoption vs Apache/MIT | Must be compatible with all inbound dependencies you distribute. |
| Contributing to OSS projects (employees) | DCO sign-off or CLA | Same | Same; FSF projects may need copyright assignment | Same | Vendor CLAs typically grant broad relicensing rights | N/A | Have an employee OSS contribution policy; CLAs can let the vendor relicense (e.g., to source-available). |
| Building on an operating system | Linux kernel is GPL-2.0-only but user-space programs are not derivative (syscall note); BSDs permissive | glibc LGPL: apps link freely | Kernel modules / drivers: GPL risk (EXPORT_SYMBOL_GPL) | N/A | N/A | N/A | Apps on Linux/Android are fine under any license; kernel modules need review. |
| Using LLM weights in a product | Apache/MIT weights: notices only | N/A | N/A | N/A | N/A | AUP compliance, thresholds, attribution, naming rules; EU restriction for some Llama multimodal models | Keep a model register: model, version, license, source URL, use case, approvals. |
| Fine-tuning / distilling LLMs | Free (Apache/MIT) | N/A | N/A | N/A | N/A | Fine-tunes and (for Gemma) distilled models are derivatives; Llama 2 barred using outputs to train other LLMs; Llama 3.1+ allows with naming rule | Also check API ToS (e.g., commercial APIs often bar using outputs to build competing models). |
| Using AI coding assistants (generated code) | Outputs may reproduce licensed snippets; license attribution/notice duties (not DMCA §1202(b)) are the main exposure | Same | Verbatim GPL snippets in distributed code create copyleft exposure regardless of the DMCA ruling | Same | Same | N/A | Doe v. GitHub (9th Cir. No. 24-7700, Sept. 16, 2026): no §1202(b) claim where the tool generates new code without CMI; "identicality" is an evidentiary gloss, and near-verbatim output can still support an inference of CMI removal. Training-data ("input") theory was forfeited, not decided; copyright and license claims are unaffected. Keep public-code filters, scan generated code, review vendor IP indemnities. |
| M&A / investment diligence | Low risk: confirm attribution compliance | Medium: confirm linking approach and source publication | High: verify no GPL in distributed proprietary products | High for SaaS targets | Check whether target depends on relicensed tools (Terraform, Elastic, Redis, MongoDB) | Check model register, thresholds post-closing (MAU/revenue), AUP | Request SBOM, scan report (Black Duck/FOSSA/Snyk), OSS policy, remediation plan. |
| Dependency maintenance / abandonment | Check maintenance status, not just license | Same | Same | Same | Vendor relicensing or wind-down of free editions is common | Model deprecations (e.g., Devstral 2 deprecated May 22, 2026) | A permissive or copyleft license does not guarantee security fixes: e.g., MinIO Community Edition (AGPL) archived Apr. 25, 2026, with no further community releases. Track maintenance status per component. |
| Group revenue / headcount growth (incl. post-acquisition) | N/A | N/A | N/A | N/A | BUSL/FSL competing-use tests may change if acquirer competes | Mistral Modified MIT (US$20M monthly consolidated revenue bar), Kimi K3 / Muse MaaS gates (affiliate revenue), Llama MAU caps; Docker/Anaconda/Oracle Java headcount or revenue metrics | Re-test every threshold on the combined group at signing and closing. |
